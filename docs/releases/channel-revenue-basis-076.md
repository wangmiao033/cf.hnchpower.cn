# 爱趣流水口径发布与回退检查

本功能只增加明细 `revenue_basis` 元数据，不回填任何账单为折后口径，不改金额、状态、收款或银行核销。旧行默认 `pre_discount`；只有明确选择并保存的爱趣明细才使用 `post_discount`。游戏 `discount_factor` 和券面值/直接扣减仍分别保留。

## 发布顺序

1. 在有明确生产操作授权、可用备份及维护窗口的前提下，先审核迁移清单和当前已应用版本。确认没有未知待执行旧迁移；禁止为了本功能盲目执行所有历史迁移。
2. 按既有审批后的独立迁移流程，仅应用 `backend/sql/076_channel_revenue_basis.sql`。下面的显式目标复用现有事务、数据库 advisory lock 和迁移校验和记录，不执行其他未应用历史迁移。该文件仅添加 `VARCHAR(24) NOT NULL DEFAULT 'pre_discount'` 和合法值约束，重复应用也不会改变金额。不要把迁移放入应用启动、业务请求或 Vercel 构建脚本。

   ```sh
   MIGRATION_EXECUTION_CONTEXT=manual PYTHONPATH=backend:. python backend/scripts/run_schema_migrations.py --only 076_channel_revenue_basis.sql
   ```

   此命令会写入生产结构及迁移记录，必须由已获授权的发布流程执行。本地验证仅覆盖驱动 SQL 参数解析、目标选择、重复运行跳过和只读检查；尚未对实际 PostgreSQL 执行迁移，不能宣称已经生产验证。
3. 使用既有安全环境变量运行只读检查（不要在命令行传入或输出数据库连接串）：

   ```sh
   PYTHONPATH=backend:. python backend/scripts/check_channel_revenue_basis_schema.py
   ```

   只有退出码 0 且 `ready: true` 才允许合并/提升含新字段读写的应用版本。缺列或检查不可达必须停止发布，旧应用继续运行；本检查不接入全局健康检查或应用启动，不制造全站启动故障。
4. 先验证新字段已可读取、历史流水和历史账单金额不变，再上线新前端和后端。未应用迁移就部署新 ORM 会造成缺列错误，因此不能颠倒顺序。
5. 对未收款、待核对的明确测试账单验证：原始流水保留原算法；折后流水不再乘游戏折扣；券面值仍转换一次、直接扣减不转换；重复保存不换行 ID；合同复算与账单算法一致。其他渠道无法启用；已核对、已收款/核销账单不自动改动。不要使用真实已核销账单进行写入测试。

## 兼容性与回退边界

- 增列后、尚未保存任何 `post_discount` 明细之前，旧应用可继续读取旧列；保留新增列即可，不要删列回退。
- 一旦已有折后明细，禁止回退到不认识 `revenue_basis` 的旧计算引擎。旧引擎可能在编辑保存时再次折扣、丢失口径，从而错误改账。
- 已启用折后口径后的故障回退，应保留支持该字段的后端、合同复算与读取能力，只回退不影响数据语义的 UI；无法保证时暂停财务写入并提供只读服务，按修复前进的方式处理。不得将折后行批量改回 `pre_discount`、把游戏折扣置 1，或修改已核销收款来适配旧版本。
- 此说明不是生产授权。本变更本地测试不会执行生产迁移或部署。发布实际结果、提交、部署 ID 和验证结论必须回填根目录 `CHANGELOG.md`。
