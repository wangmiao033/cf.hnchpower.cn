# 财务管理系统生产运行手册

本文档用于 `cf.hnchpower.cn` 的正式发布、日常巡检、故障处理与回滚。不得在仓库中提交任何真实密钥、密码或数据库连接串。

## 1. 生产环境基线

生产环境必须配置以下变量：

| 变量 | 必需 | 说明 |
| --- | --- | --- |
| `APP_ENV=production` | 是 | 启用生产环境安全行为 |
| `DATABASE_URL` | 是 | PostgreSQL 连接串，建议使用连接池地址 |
| `AUTH_JWT_SECRET` | 是 | 足够长的随机会话签名密钥 |
| `AUTH_BUILTIN_ACCOUNT` | 建议 | 首个管理员账号名 |
| `AUTH_BUILTIN_PASSWORDS` | 首次初始化必需 | 首个管理员初始密码；完成初始化后应轮换 |
| `AUTH_SESSION_HOURS` | 建议 | 会话有效期，默认 8 小时，范围 1–168 |
| `AUTH_COOKIE_SECURE=true` | 是 | 仅通过 HTTPS 发送认证 Cookie |
| `AUTH_COOKIE_SAMESITE=lax` | 建议 | 当前同站点部署的安全默认值 |
| `BLOB_READ_WRITE_TOKEN` | 使用附件时必需 | 私有账单附件存储令牌 |
| `AUTO_MIGRATE_DB=1` | 按部署策略 | 允许启动时执行数据库迁移 |

生产环境不应设置宽泛的 `CORS_EXTRA_ORIGINS`。需要新增来源时，应逐个填写完整 HTTPS Origin。

## 2. 发布前检查

每次发布必须满足：

1. GitHub `Production Quality Gate` 的前端和后端任务均通过。
2. Vercel Preview 状态为 `READY`。
3. Preview 的 `/health` 返回 HTTP 200 和 `{"ok":true}`。
4. 数据库迁移已核对，禁止在没有备份的情况下执行破坏性迁移。
5. 变更涉及新增、编辑、删除或金额计算时，至少回归对应业务流程。
6. 不允许把账号、密码、Token、数据库连接串或客户敏感数据写入代码和日志。

## 3. 发布后冒烟检查

生产部署完成后依次检查：

```text
GET https://cf.hnchpower.cn/health
预期：HTTP 200，{"ok":true}

GET https://cf.hnchpower.cn/health/db
预期：HTTP 200，{"ok":true,"database":"connected"}

GET https://cf.hnchpower.cn/api/auth/me（未登录）
预期：HTTP 401
```

随后使用测试账号完成：

1. 登录与退出。
2. 打开总览、研发账单、渠道账单、对账进度、合同、发票、数据库和客户库。
3. 新建一条测试账单并保存，再编辑和删除。
4. 验证金额计算、筛选、分页和导出。
5. 在测试账单上上传、查看、下载并删除一个附件。
6. 修改测试账号密码，确认当前设备仍可使用、其他设备会话已失效。

测试数据完成后必须删除。

## 4. 日常巡检

建议每个工作日检查：

- `/health` 与 `/health/db`。
- Vercel 最近 24 小时 Runtime Errors。
- PostgreSQL 连接数、存储空间、慢查询与备份状态。
- 私有 Blob 存储容量和异常上传。
- 合同到期风险、待核对账单、未关联发票和未完成付款。

发现持续 5xx、数据库连接失败或金额异常时，应暂停批量导入及删除操作。

## 5. 数据备份

数据库是核心业务数据源。必须在数据库供应商侧启用自动备份，并确认：

- 至少每日备份一次。
- 保留周期不少于 14 天。
- 在重大迁移、批量导入和结构调整前创建手动快照。
- 每季度至少完成一次恢复演练，确认备份可实际恢复。

Vercel 部署历史不能替代数据库备份。Blob 附件也应按存储服务能力配置保留或复制策略。

## 6. 回滚流程

出现严重问题时：

1. 暂停新增、编辑、删除和批量导入。
2. 在 Vercel 中将上一个已验证的生产 Deployment 重新提升为 Production。
3. 检查 `/health` 与 `/health/db`。
4. 若问题涉及数据库迁移，先评估数据兼容性，不得盲目回滚代码。
5. 必要时从发布前快照恢复数据库，并记录受影响时间段和数据范围。
6. 回滚后检查 Vercel Runtime Errors，并完成核心业务冒烟测试。

## 7. 故障分级

### P0：立即处理

- 系统无法登录或全部页面不可用。
- 数据库不可连接。
- 金额被错误写入、批量丢失或出现越权访问。
- 密钥、密码或客户敏感数据泄露。

处理：立即停止写入、回滚、轮换密钥并核对数据。

### P1：当日处理

- 单个核心模块持续报错。
- 附件无法上传或读取。
- 导入、导出、编辑或删除功能不可用。
- 大量请求超时或出现重复数据。

### P2：排期处理

- 非阻塞 UI 问题。
- 少量文案、间距和响应式异常。
- 不影响结果的性能或体验问题。

## 8. 安全操作要求

- 不共用管理员账号，正式使用时为每位操作人员建立独立账号。
- 人员离职或权限变化时立即停用账号。
- 管理员重置密码后，目标账号所有旧会话必须失效。
- 禁止通过聊天工具发送明文生产密码和数据库连接串。
- 公共电脑使用后必须退出登录。
- 发现异常登录或数据操作时，先停用账号并保留日志。

## 9. 发布记录

每次生产发布至少记录：

- 发布时间与负责人。
- Git Commit 和 Vercel Deployment ID。
- 主要变更。
- 数据库迁移编号。
- 冒烟测试结果。
- 是否创建数据库快照。
- 已知问题和回滚目标版本。
